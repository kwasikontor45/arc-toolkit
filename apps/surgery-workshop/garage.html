Calendar refresh

Read path · Orage stays the source of calendar events and to-dos.

  1. 1 · BrowserWhile Khaos Hub is open, its page requests a fresh snapshot on a short interval.
  2. 2 · Local HubThe loopback service reads Orage and joins Hub-owned completion marks.
  3. 3 · VerifyCompare the rendered list with Orage. This guide makes no request and reads no calendar data.
Where this lives
  • apps/khaos-hub/web/app.js · refreshCalendar()
  • bin/khaos-hub · calendar_items() / snapshot()
  • ~/.local/share/orage/orage.ics · source calendar

◇Boundary: refresh reads calendar state; it does not modify Orage or completion marks.

Mark an item complete

Narrow write · only the Hub’s completion state changes.

  1. 1 · BrowserA deliberate check sends the item ID, desired state, and revision.
  2. 2 · Local HubThe loopback service checks origin, token, content type, and revision before saving.
  3. 3 · VerifySQLite stores the mark and next revision. Orage text, status, and alarms stay unchanged.
Where this lives
  • apps/khaos-hub/web/app.js · makeRow()
  • bin/khaos-hub · Handler.allowed() / set_checked()
  • ~/.local/share/khaos-hub/checks.db · Hub-owned marks

◇Boundary: checking an item does not edit the Orage calendar.
